# CLAUDE.md — Платформа (web-desktop / репозиторий SUE_system)

Этот файл — контекст проекта для Claude Code. Прочитай его перед работой над репозиторием.

## Что это

Браузерный «рабочий стол» (web-desktop): единая оболочка, в которую пользователь логинится один раз и открывает приложения окнами внутри неё. Поверх — единый вход (SSO через Keycloak), права доступа (RBAC) и общий центр уведомлений.

Важно: **оболочка не содержит бизнес-логики приложений.** Каждое приложение (СИЗ-контроль, Склад, Отчёты, …) — отдельный задеплоенный сервис со своим URL. Оболочка лишь открывает их в `iframe` и собирает воедино. Не тащи сюда код или данные конкретных приложений.

## Стек

React + Vite. Окна — `react-rnd` (перетаскивание/ресайз). Состояние — `zustand`. Вход — `keycloak-js`. Иконки — `lucide-react`. Прод-сборка — Docker + nginx, деплой на Amvera.

```

  auth/

    useAuth.js             — хук useAuth()
  config/
    apps.js                — РЕЕСТР приложений + appsForRoles(roles) (фильтр по правам)
    wallpapers.js          — набор обоев рабочего стола
  store/
    useDesktopStore.js     — менеджер окон и уведомлений (zustand)
  hooks/

  components/

    Dock.jsx               — нижний док (таскбар: только ОТКРЫТЫЕ приложения, SVG-иконки)
    AppIcon.jsx            — иконка приложения: инлайн-SVG плитка (iconSvg), легаси картинка (iconUrl), откат на lucide
  config/appIcons.jsx      — инлайн-SVG плитки приложений (SvetTile, SizTile, …)
    WindowFrame.jsx        — окно (перетаскивание/ресайз через react-rnd)
    AppFrame.jsx           — iframe приложения + передача токена
    NotificationCenter.jsx — колокольчик и панель уведомлений
```

Конкретику всегда сверяй по самим файлам — дерево выше для ориентира.

## Правила (соблюдать)

- **Стили — только через `src/theme/tokens.css`.** Компоненты не содержат собственных цветов/размеров — лишь CSS-переменные из токенов. Меняешь внешний вид — правь токены, а не компоненты.
- **Новое приложение добавляется в `src/config/apps.js`** (id, название, иконка из lucide, URL, нужные роли). Больше нигде трогать не нужно — `Desktop` и `Dock` рендерятся из реестра.
- **Окна и уведомления — через `useDesktopStore`** (zustand): открытие/закрытие/фокус/восстановление окна и push уведомлений живут там.
- **Контракт авторизации с приложениями:** после загрузки iframe оболочка шлёт приложению токен через `postMessage` сообщением `{ type: 'platform-auth', token: '<JWT>' }`. Приложение на своей стороне слушает это и **обязано проверять `origin`**. Формат сообщения без причины не меняй — на него завязаны приложения.
- **`iframe` в `AppFrame`** идёт с `sandbox="allow-same-origin allow-scripts allow-forms allow-popups allow-downloads"`. Не ослабляй песочницу без необходимости.
- **Секреты в репозиторий не коммить.** `.env` здесь — обычный фронтенд-конфиг (URL-адреса). Реальные секреты Keycloak живут в его админке/окружении, а не в коде.

## Запуск и сборка

```
npm install
npm run dev        # http://localhost:5173
npm run build      # прод-сборка в dist/
```

## Режимы входа

- **Dev / демо:** `.env` с `VITE_AUTH_DISABLED=true` — заходишь без Keycloak под тестовым пользователем и сразу видишь интерфейс. В центре уведомлений в этом режиме есть кнопка «+ тестовое уведомление».
- **Боевой:** Keycloak. Переменные: `VITE_KEYCLOAK_URL`, `VITE_KEYCLOAK_REALM`, `VITE_KEYCLOAK_CLIENT`. Адреса приложений: `VITE_APP_SIZ_URL` и аналогичные.

## Деплой

Amvera, Docker-проект. `Dockerfile` собирает Vite и отдаёт статику через nginx. `nginx.conf` — SPA-роутинг (любой путь → `index.html`) плюс долгий кэш на `/assets/`. `amvera.yml` — порт 80.

## Текущее состояние и план

Боевой вход через Keycloak работает. Приложения подключаются по единому паттерну (см. ниже).

**Подключено и работает:**
- **«Светлячок»** (Учёт ПУ, репозиторий `Uchet_PU_amvera`, `uchet-pu-amvera-ashinoff.amvera.io`) — единый вход работает в проде (2026-07-08). Роль доступа в Keycloak: `svet-user`.

**Эталонный паттерн интеграции приложения (по «Светлячку»):**
1. В `apps.js` — запись приложения с `roles: ['<app>-user', 'admin']` и URL (env `VITE_APP_*_URL`).
2. В Keycloak завести ОДНУ realm-роль доступа `<app>-user` и выдавать её пользователям (+ заполнять email в профиле).
3. На стороне приложения: принять токен платформы (`platform-auth`), проверить по JWKS, найти своего пользователя **по email**, а роль/права взять из СВОЕЙ БД. То есть Keycloak решает «кто ты» + «пускать ли» (одна роль), приложение — «что тебе можно».

**Добавлено в реестр (`apps.js`):**
- **РЭС-менеджмент** (`res-management_amvera`, Node/Express) — запись `resm`,
  роль доступа `resm-user`, `badge:true`, URL из `VITE_APP_RESM_URL`
  (в `.env.production` пока best-guess `res-management-amvera-ashinoff.amvera.io`
  — **проверить реальный домен**). Плитка `ResmTile`. Приложение со стороны
  бэка уже интегрировано (Keycloak SSO по email + `/api/platform/badge`).
  Осталось: в Keycloak завести realm-роль `resm-user` + выдать пользователям
  (с email); на Amvera res-management выставить env (`PLATFORM_SSO=true`,
  `ACCESS_ROLE=resm-user`, `PLATFORM_ORIGIN`, `KEYCLOAK_*`).

**В работе:** СИЗ-контроль (`siz-control`) переводится на тот же паттерн (email + одна роль `siz-user` вместо множества ролей в Keycloak).

## Иконки, док и бейджи (UI рабочего стола)

Всё рендерится из реестра `apps.js`. Правки внешнего вида иконок — в `AppIcon.jsx` и `app.css` (классы `.app-icon*`).

- **Иконки-плитки (инлайн-SVG, приоритет).** У приложения в `apps.js` —
  `iconSvg: <Tile>` из `src/config/appIcons.jsx` (вектор, без картинок): плитка
  = скруглённый квадрат с фирменной заливкой + белый глиф. Сейчас: `SvetTile`
  (тёплый→холодный градиент, белая молния) и `SizTile` (красная, белый
  щит-галочка). `AppIcon.jsx` рендерит `iconSvg` как `<svg class="app-icon__img">`
  — заполняет плитку целиком, а подложка-бейдж прозрачна через
  `.app-icon__badge:has(.app-icon__img)`. Новые приложения — добавляй свою
  плитку в `appIcons.jsx`.
- **Легаси `iconUrl` (картинки).** `iconUrl: '/apps/<id>.png'` из `public/apps/`
  ещё поддерживается (`AppIcon` покажет `<img class="app-icon__img">` при
  отсутствии `iconSvg`; откат на lucide `icon` при ошибке). Если картинка — она
  должна быть **без белых полей** (обрезана в край). Ушли от PNG к `iconSvg`.
- **Док (таскбар)** использует lucide `icon` (мелкий штриховой глиф), НЕ плитку —
  так и задумано.
- **Док = таскбар.** `Dock.jsx` показывает ТОЛЬКО открытые приложения (у которых есть окно в `useDesktopStore.windows`); нет окон — док пуст и скрыт (`.dock:empty`). В доке — **SVG-иконки (lucide)**, не картинки. Клик восстанавливает/фокусирует окно.
- **Бейджи уведомлений (iOS-стиль).** У приложения с бэкендом — `badge: true` в `apps.js` (заглушки без API — `false`). Хук `useAppBadges.js` опрашивает `GET ${app.url}/api/platform/badge` с `Authorization: Bearer <Keycloak-токен>` при загрузке, каждые 60с и на `visibilitychange`; ответ `{count}`. Любая ошибка/401/таймаут — **тихо**, бейдж не показываем. `Desktop.jsx` рисует красный кружок (`.app-icon__notif`) в углу иконки: `count>0` — показать, `>99` — «99+», `0` — скрыть. **Контракт бейджа:** приложение обязано отдавать `GET /api/platform/badge` → `{"count": N}`, проверяя тот же Keycloak-токен и разрешая CORS для origin платформы (см. `platform-sso` в приложениях).

> Примечание: цвета бейджа (`#ff3b30`, `#fff`) заданы прямо в `app.css`, а не через токены — это осознанное отступление от правила «стили только через tokens.css» для стандартного iOS-красного. При желании — вынести в токен.
